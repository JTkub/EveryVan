# EveryVan

ระบบจองตั๋วรถตู้ประกอบด้วย React + TypeScript + Vite, Flask API และ PostgreSQL

## การใช้งานข้อมูลจริง

เว็บอ่านและบันทึกข้อมูลผ่าน Flask API และ PostgreSQL เท่านั้น หากเชื่อมต่อไม่ได้จะแสดงข้อผิดพลาด ไม่มีการสร้างข้อมูลสำรองจำลองในเบราว์เซอร์ ไม่มีการ seed บัญชี รถ หรือเส้นทางทดลอง และไม่มี OTP ที่รับเลขใดก็ได้

**การโอนเงินและปุ่มจำลองการชำระเงินยังเป็น Demo ตามข้อกำหนด** ส่วนการจอง การออกตั๋ว และการสแกนเช็กอินบันทึกในฐานข้อมูลจริง

สร้างบัญชีผู้ดูแลจริงด้วยรหัสผ่านที่กำหนดเอง:

```powershell
python -m api.create_admin --username owner --email owner@example.com --name "ชื่อ นามสกุล"
```

หากรัน Docker ใช้ `docker compose exec api python -m api.create_admin` ตามด้วยอาร์กิวเมนต์เดียวกัน ระบบถามรหัสผ่านโดยไม่พิมพ์ออกหน้าจอ จากนั้นผู้ดูแลเพิ่มบัญชีพนักงานและคนขับผ่านเมนูจัดการบัญชี ผู้โดยสารสมัครเองได้

บัญชีทดลองเดิมที่ยังใช้ชื่อ อีเมล และรหัสผ่านเริ่มต้นครบทั้งสามอย่างจะถูกปิดใช้งานและถอน session เมื่ออัปเดตระบบ ประวัติการจองยังอยู่ บัญชีที่เปลี่ยนข้อมูลหรือรหัสผ่านแล้วจะไม่ถูกปิดอัตโนมัติ

## สแกนตั๋วและคิวประจำ

- คนขับสแกน QR แล้วระบบตรวจสิทธิ์คนขับ การชำระเงิน วันที่เที่ยว และสถานะเที่ยวรถ จากนั้นเช็กอิน (`paid → boarded`) พร้อมบันทึกเวลาในคำขอเดียว สแกนซ้ำไม่บันทึกซ้ำ
- พนักงานจัดคิว ผู้ควบคุมคิว และผู้ดูแลใช้หน้า **เพิ่มเที่ยวรถ → คิวสายประจำอัตโนมัติ** เพื่อเพิ่มหรือแก้สาย เวลาออก วันที่เริ่ม ระยะเวลา รถ คนขับ ค่าโดยสาร และจุดลง รวมถึงพัก/เปิดสาย
- สร้างคิวทุกวันในช่วง 7 วันนับจากวันนี้ตามเวลาไทย โดยข้ามเวลาออกที่ผ่านไปแล้ว ป้องกันเที่ยวซ้ำด้วยฐานข้อมูล
- แก้สายประจำเฉพาะเที่ยวอนาคตที่ยังรอ ไม่มีผู้จอง และไม่ถูกปรับเวลาเฉพาะวัน เที่ยวที่มีผู้จองหรือถูกปรับเฉพาะวันคงเดิม การพักสายใช้กติกาเดียวกัน
- ต้องเปิด background scheduler ไว้เพื่อสร้างคิวโดยไม่ต้องมีคนเปิดเว็บ: `npm start` เปิด API เว็บ และ scheduler หรือ `npm run scheduler` แยกต่างหาก Docker Compose มีบริการ `scheduler` ให้แล้ว
- State diagrams อยู่ใน `state-diagrams/` ดูรายการเปลี่ยนแปลงใน `state-diagrams/README.md`

## ทดสอบ

`npm run check` ตรวจ lint, frontend tests, build และ Python unit tests

`npm run test:smoke` หรือ `python scripts/test-postgres.py` ทดสอบกับ PostgreSQL แยกชั่วคราว แล้วปิดและลบฐานทดสอบ ไม่ใช้บัญชีทดลองหรือฐานข้อมูลจริง ตั้ง `PG_BIN` หาก PostgreSQL ไม่ได้อยู่ที่ `C:/Program Files/PostgreSQL/18/bin`

บัญชี `admin` เป็นสิทธิ์สูงสุดของระบบ เมนู **จัดการบัญชี** ใช้สำหรับ:

- เพิ่มและแก้ไขบัญชีพนักงานจัดคิว ผู้ควบคุมคิว ฝ่ายบัญชี และคนขับ
- เปลี่ยนบทบาท รีเซ็ตรหัสผ่าน และเปิด/ปิดการใช้งานบัญชีพนักงาน
- ค้นหา แก้ไขข้อมูล รีเซ็ตรหัสผ่าน และเปิด/ปิดการใช้งานบัญชีลูกค้า
- ผู้ใช้ทุกบทบาทเปลี่ยนรหัสผ่านของตัวเองได้จากหน้า **ข้อมูลส่วนตัว**

ระบบไม่สร้างบทบาท Super Admin เพิ่ม บัญชีผู้ดูแลเดิมยังคงเป็นระดับสูงสุด

## รันด้วย Docker Compose

1. สร้างไฟล์ค่าระบบจากตัวอย่าง (ทำครั้งแรก หรือเมื่อรับโปรเจกต์จาก GitHub):

```powershell
Copy-Item .env.example .env
```

แก้รหัสผ่านฐานข้อมูลใน `.env` ให้เป็นค่าของคุณเองก่อนรันระบบ และให้ `DATABASE_URL` ใช้รหัสผ่านเดียวกัน ไฟล์ `.env` ไม่ถูกอัปโหลดขึ้น GitHub

2. สร้าง volume เก็บข้อมูล (คำสั่งนี้รันซ้ำได้):

```powershell
docker volume create everyvan-db-data
```

3. Build และเปิดบริการเว็บ API ฐานข้อมูล และ scheduler:

```powershell
docker compose up -d --build
```

4. ตรวจสถานะ:

```powershell
docker compose ps
```

เปิดใช้งาน:

- เว็บ: http://localhost:8000
- API health: http://localhost:5000/api/health
- PostgreSQL จากเครื่อง host: `localhost:5433`

### หยุดและรันใหม่

1. หยุดโดยเก็บข้อมูลไว้:

```powershell
docker compose down
```

2. รันใหม่:

```powershell
docker compose up -d
```

3. Build ใหม่หลังแก้โค้ด:

```powershell
docker compose up -d --build
```

4. ดู log:

```powershell
docker compose logs -f
```

กด `Ctrl+C` เพื่อออกจากหน้าดู log โดย container ยังทำงานต่อ

### ล้างฐานข้อมูลทั้งหมด

คำสั่งต่อไปนี้ลบข้อมูล PostgreSQL ใน Docker อย่างถาวร:

```powershell
docker compose down; docker volume rm everyvan-db-data
```
ก่อนรันควรสำรองข้อมูลหากมีข้อมูลที่ต้องเก็บ
